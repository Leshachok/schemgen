# compose-renderer

The Compose Multiplatform renderer for schemgen (D31, D32), as three Gradle modules:

- **`schemgen-renderer-compose`** is the library: Android, iOS (arm64, simulator arm64) and
  wasmJs. It's published as `ua.gov.uz:schemgen-renderer-compose` to the `UZmiv-internal` Azure
  Artifacts feed, set up the same way as `uz-compose-ui-kit`, and to `UZmiv-public` for external teams. Consumers and the
  miv-multiplatform hand-off are in [INTEGRATION.md](INTEGRATION.md). How to release is
  in `/build.md`.
- **`composeApp`** is the wasm preview harness that the Preview tab in `web/index.html`
  talks to via `postMessage`. It has no renderer code of its own.
- **`sampleApp`** is an Android demo, the counterpart of `vue-renderer/sampleApp`: the web
  builder's samples as one long, vertically scrolling list of wagons, each scrolling
  horizontally, with a switch between two versions of the same screen. **Views** is a
  RecyclerView whose rows host the renderer in a `ComposeView`, the way the Android sales
  app (legacy Views) will; **Compose** is a LazyColumn. A View/Select switch, an availability
  menu and a per-wagon selection show the app's side of the contract (D45, D46). Wagons can
  be added from the samples, ten at a time, or as pasted JSON, to see how a long list scrolls.

## Verification status

Builds, tests pass, and renders schemes sent by postMessage. Verified 2026-10-05, and
again after the library split on 2026-10-06. Details are in
`docs/wagon-scheme-format.md` §11.

```
./gradlew :composeApp:wasmJsBrowserDevelopmentRun       # harness on http://localhost:8080
./gradlew :schemgen-renderer-compose:wasmJsBrowserTest           # commonTest in headless Chrome
./gradlew :schemgen-renderer-compose:iosSimulatorArm64Test       # same tests, iOS simulator
./gradlew :schemgen-renderer-compose:publishToMavenLocal         # try it in a consumer
./gradlew :sampleApp:installDebug                                # Android demo
./gradlew :sampleApp:installRelease                              # the same, R8-minified
```

Judge scrolling on the release build: a debug build runs Compose without optimization and
scrolls noticeably worse than any shipped app. The release build is minified and shrunk
with R8 like a real one, signed with the debug key only so it installs without a keystore,
and `profileable`, so `adb shell dumpsys gfxinfo ua.gov.uz.schemgen.sample` and the Android
Studio profiler can measure it. The sample list is the web builder's (`web/js/schemes.js`),
exported to `sampleApp/src/main/assets/samples.json` by `node
compose-renderer/sampleApp/export-samples.mjs`; rerun it when the builder's samples change.

(`wasmJsBrowserRun`, the name used in older notes, no longer exists in current
Kotlin.) Configuring the build needs an Android SDK: `ANDROID_HOME` or `sdk.dir` in
an untracked `local.properties`.

Drawn to the guidelines file "Wagon components" (D50–D52), like the web builder. Item
boxes and deck sizes are tested against `format.js`'s own output for the shared
fixtures; pixel parity of the drawing itself needs the golden fixture suite (roadmap
phase 3).

## Module map

```
schemgen-renderer-compose/src/
  commonMain/kotlin/ua/gov/uz/schemgen/
    model/Scheme.kt          public: data classes mirroring the JSON format 1:1
    model/SchemeParser.kt    public: hand-written parser (the format isn't a clean
                              tagged union, so this mirrors web/js/format.js's own
                              duck-typed dispatch rather than fighting
                              kotlinx.serialization's polymorphism)
    layout/SeatState.kt      public SchemeMode; internal seat state rule (D45)
    layout/Validate.kt       public: structural validation, same rules as format.js
    layout/Layout.kt         internal: layout math, ported line-for-line from format.js
    render/SchemeCanvas.kt   public SchemeView composable
    render/SchemeColors.kt   public theme, colors only (D34)
    render/Icons.kt          internal: element art, generated by web/tools/figma_icons.py
                              from the same exports as web/js/icons.js
  commonTest/kotlin/ua/gov/uz/schemgen/   fixture-based parser/validator/layout tests
composeApp/src/wasmJsMain/
  kotlin/ua/gov/uz/schemgen/main.kt       harness entry point + postMessage listener
  resources/index.html                    HTML shell for the wasmJs build
sampleApp/src/main/
  kotlin/ua/gov/uz/schemgen/sample/
    Wagons.kt              app state: wagon list, mode, availability, selection
    WagonScheme.kt         the renderer as both screens host it (horizontal scroll)
    ViewsFragment.kt       RecyclerView + ComposeView per row
    ComposeFragment.kt     LazyColumn
    MainActivity.kt        Views shell: screen and mode switches, menu, add dialogs
  assets/samples.json      generated by sampleApp/export-samples.mjs
```

Anything not listed as public is `internal`, so the published API stays as small as
INTEGRATION.md describes. Making something public is an API decision (D32), not a
convenience.

## Keeping this in sync with the JS reference

`layout/Layout.kt` and `layout/Validate.kt` are ports, not independent
implementations — if `web/js/format.js` changes, these should change with it.
There's no automated check for that yet (roadmap phase 2, golden fixture
parity); until then it's a manual discipline.

`vue-renderer/schemgen-renderer-vue` is in turn a file-for-file port of this module (D53):
the same files, functions and public API. A change here goes into the file of the same
name there, in the same change. Its tests run `format.js` itself on every shared fixture,
so the Vue side is checked against the reference even though this side isn't yet.
